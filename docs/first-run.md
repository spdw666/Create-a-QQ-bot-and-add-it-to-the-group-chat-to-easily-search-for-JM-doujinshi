# 新电脑首次运行（Windows）

这套流程面向没有 Python 环境的新 Windows 10/11 电脑。项目会自动创建独立虚拟环境、安装 Python 依赖、创建本地 `.env`，并启动机器人与 HTTP 分享服务。

## 只需做一次的外部准备

QQ/NapCat 的登录和公网网络配置无法由项目自动完成：需要操作者本人扫码/登录 QQ，且如果希望群成员使用机器人给出的浏览器链接，需让公网能够访问本机的 HTTP 端口。

1. 安装并登录 [NapCat](https://napneko.github.io/)；使用专门的机器人 QQ 账号。
2. 在 NapCat 创建 **OneBot v11 正向 WebSocket 服务端**，监听地址填写 `127.0.0.1`、端口填写 `8081`。这是机器人连接 NapCat 的固定本地地址。
3. 若需要浏览器下载链接，在防火墙/路由器/云安全组中放行 TCP `8080`，并准备公网 IP 或域名。仅测试群文件上传时可跳过这一步。

> 不要把 QQ 密码、二维码、token、Cookie 或 `.env` 提交到 Git 或发到群里。

## 一键启动

1. 下载/克隆仓库并解压到一个普通目录，路径不要包含需要管理员权限的受保护目录。
2. 双击仓库根目录的 `start_jmniang.bat`。
3. 第一次运行时，脚本会尝试通过 `winget` 安装 Python 3.11；之后创建 `.venv` 并安装机器人核心依赖。首次安装需要几分钟。
4. 按提示输入公网 IP 或域名；若直接回车，机器人仍会运行，但 HTTP 链接只对本机有效。脚本会自动生成 ZIP 密码并保存到本地 `.env`。
5. 当检查显示 NapCat 已就绪后，JM娘和本地 HTTP 分享服务会在同一窗口启动。群内 @机器人发送 `自查` 应能看到连接和缓存状态。

以后再次启动，直接双击 `start_jmniang.bat` 即可；没有改动 `requirements.txt` 时不会重复安装依赖。

### 可选：启用本地 OCR

图片识别在没有本地 OCR 时仍可使用 iQDB、已配置的 SauceNAO、视觉模型等路径；只是缺少图片文字提取。OCR 依赖包含 ONNX/OpenCV 等大包，网络不稳定时不应阻塞机器人启动。网络恢复后在项目根目录执行：

```powershell
.\scripts\install_ocr.ps1
```

完成后重启机器人，群内发送 `自查`，识图链路应显示 `OCR` 而非 `OCR（未安装）`。

## 配置位置与常用项

所有本机配置都在根目录 `.env`（已被 Git 忽略）。停止机器人后再修改它，然后重新启动。

| 变量 | 何时需要修改 |
|---|---|
| `JM_ZIP_PASSWORD` | 自动生成；需要在可信渠道告知有解压需求的用户。 |
| `JM_PUBLIC_IP` | 改为当前公网 IP、DDNS 域名或可访问的内网 IP。 |
| `JM_HTTP_PORT` / `JM_HTTP_BIND` | 默认 `8080` / `0.0.0.0`；端口被占用或网络策略不同才改。 |
| `JM_PROXY` | 本机访问所需站点必须经过代理时填写，例如 `http://127.0.0.1:7890`。默认留空。 |
| 其余 `JM_*` 项 | 识图、管理员、订阅等增强能力；见根目录 `.env.example`。 |

## 自查与常见失败

| 现象 | 处理 |
|---|---|
| 脚本提示找不到 Python | 安装 Python 3.11 并勾选 PATH，或让 `winget` 完成安装后重新双击。 |
| 脚本提示 NapCat 不可达 | 确认 QQ 已登录，且 NapCat 的服务类型是“正向 WebSocket 服务端”、地址 `127.0.0.1`、端口 `8081`。 |
| 群文件可收到，浏览器链接打不开 | 检查 `.env` 的公网地址、Windows 防火墙、路由器端口转发或云安全组的 TCP `8080`。 |
| 8080 端口被占用 | 修改 `JM_HTTP_PORT`，同时在网络侧放行新端口；或用 Nginx 托管仓库的 `http_dl/` 目录。 |
| 启动后访问站点失败 | 按需设置 `JM_PROXY`，然后重启。 |
